# PocketServer P0 threat model and regression matrix

The v3 implementation plan identifies F01–F25 against baseline `7d84f56`. This document records the decisions and the evidence needed to close each finding. **Every row is planned acceptance coverage.** Its suite name identifies where to exercise the completed behavior. A P0 fixture or baseline characterization can establish what the existing code does. Closing a finding requires the relevant phase to deliver its fix and record a passing behavioral check on the applicable platform.

P0 characterization now exists in `tests/test_p0_safety.py`: three checks pass and two strict expected failures reproduce F01/F03 using intercepted process probes and temporary configuration. These are baseline observations, not acceptance evidence closing either defect. The successful run disables incompatible external pytest plugins; commands and limitations are recorded in `MULTI_MODEL_EXECUTION_PLAN.md`.

## Assets, actors and exposure

One owner controls a non-root Termux account. Protect the password hash, session key, session records, SSH identity, file vault, repositories and private backups. Preserve user data across install, migration and recovery. A service operator also depends on accurate observations of ownership, readiness, network exposure and disk capacity when deciding whether to start, stop or recover a service.

Treat network clients, browser origins, names, uploaded bytes, logs and imported archives as untrusted. A full-shell owner key, locally registered job and custom API program carry the owner's authority. Same-UID programs can read Termux files and alter them outside application locks. Git-only keys have a separate, restricted role. Restore quarantines imported API/job trees by default and always quarantines Git hooks while rebuilding allowlisted repository settings. Archive checksums establish content integrity only.

The dashboard and its control API listen on loopback. Remote administration uses SSH local forwarding. Validate effective Host and origin, require CSRF on browser mutations including login/logout, and enforce server-side session revocation. Require recent authentication for key changes, publication, destructive deletion and backup downloads. Web/API exposure requires an explicit owner decision. Public listeners must exclude control functions, the private vault, administrative telemetry and cookie logging. Only a ready web/API service can be selected for a Quick Tunnel. Each publication requires fresh consent after loss or restart.

## Ownership, durability and containment

- Production runs in app-private Termux storage under runit. Scope operations to owned service directories. Treat PID files, marker files, log URLs and open sockets as observations. On Windows, use an isolated fake backend. A POSIX integration harness can retain and reap its own child handles. Tests use unique temporary roots and synthetic credentials.
- One controller dispatches bounded, idempotent operations. Acquire maintenance, operation, configuration and resource locks in that order when needed. A maintenance writer waits outside the operation mutex so active work can complete or cancel. Running writers hold shared maintenance protection. Restore and consistent backup require exclusive access, including quiescence of SSH/Git writers.
- Only explicit initialization creates private state. Inspectors preserve damaged files and report uninitialized or recovery-required state. Revision checks prevent stale writes. Authentication generation advances on credential changes and restore. An unfinished restore journal blocks service startup and mutation through every entry point until recovery completes.
- Open files relative to verified directory descriptors. Budget listener buffers **before** startup, counting concurrent requests before authentication. Reserve upload staging and archive work separately and preserve 250 MiB of headroom. Reject unsupported secure file operations on a platform that lacks them. Imported data and abnormal job output cannot consume unbounded storage.

## Open release evidence

Physical ARM64 Termux qualification is outstanding. Record Android/OEM, Termux, architecture, Python and package versions. Establish compiler-free installation on a clean device, private filesystem operations, runit ownership and restart limits, SSH/Git behavior, network publication/revocation, and recovery after an actual reboot. Record terminal closure, a 30-minute screen-off run, network changes, child crash, force-stop and relaunch, and unavailable optional APIs. An eight-hour controlled soak must account for disk growth, open descriptors, owned children and thermal/battery observations. Additional Android versions require representative device evidence before claiming support. Track unavailable hardware, network access or required review as blocked in the release matrix.
